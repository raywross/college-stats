## Data Access (`lib/data.ts` → `lib/dataset.ts`)

Server code gets the loaded dataset once and destructures the queries it needs. Every query is synchronous and
in memory:

```typescript
import { getData } from "@/lib/data";

export default async function Page() {
  const data = await getData();
  const { getSchoolById, rankOf } = data;
  const tags = standouts(data, school); // lib/insights.ts functions take the dataset first
}
```

- `lib/data.ts` (server-only): `getData()` loads from `data/*.json` or Supabase (`DATA_SOURCE`,
  [supabase.md](supabase.md)) and keeps it in memory through `lib/dataset-loader.ts`, which reloads when Supabase
  serves a newer publish ([supabase.md](supabase.md#revalidation)). Also re-exports `paginate`, `toIndexEntry`, and the
  `Dataset`, `SchoolIndexEntry`, and `ScatterPointData` types.
- `lib/dataset.ts` (pure): `createDataset({ schools, meta, releaseCalendar })` returns the query functions as
  closures, so they destructure safely. Per-metric sorted arrays are cached per dataset, so a reload never mixes
  in old ranks.
- Components that show ranks or citations are async server components that call `getData()` themselves. It's
  cached per request, so they share one copy.

| Function | Signature | Description |
|---|---|---|
| `getSchools` | `(filters: SearchFilters) => School[]` | Search and filter schools |
| `getSchoolById` | `(id: string) => School \| null` | Get single school |
| `getSchoolsByIds` | `(ids: string[]) => School[]` | Get multiple for comparison |
| `getStates` | `() => string[]` | Distinct states in data |
| `getAllSchools` | `() => School[]` | Entire dataset |
| `searchSchools` | `(q, limit?, exclude?) => SchoolIndexEntry[]` | Typeahead (served by `/api/schools`) |
| `rankOf` | `(school, MetricKey) => number` | 0–1 share of other schools below this value |
| `metricMedian` / `metricValues` / `distribution` | `(MetricKey)` | Dataset median / all values / binned strip |
| `getDatasetSummary` | `()` | Totals for the home page |
| `countByState`, `topBy`, `histogram` | | Map, leaderboards, filter histograms |
| `citeField`, `sourcesForFields`, `sourcesForSchools`, `getMeta`, `getReleaseCalendar`, `cdsSchools` | | Citations and the Data page |

## Derived metrics (`lib/metrics.ts`)
`satComposite`, `satMid`, `actMid`, `yieldRate`, `oneIn`, `diversityIndex` (Simpson's), `selectivityTier`,
`sizeBucket`. The `METRICS` registry maps each `MetricKey` to its getter, formatter, domain color, and glossary term.

Percentiles and medians are computed against the full loaded dataset, whichever store it came from.

## Dataset (`data/schools.json`)
~1,900 operating 4-year colleges, generated by `npm run sync-data`. See [data-sync.md](data-sync.md).
With `DATA_SOURCE=json`, `lib/data.ts` reads it once per server process with `fs` (not a JSON import, which would
make TypeScript infer a huge literal type). With `DATA_SOURCE=supabase`, it reads the copy published by
`npm run publish-data`. The browser never receives the full list: client components call `/api/schools` (`?q=`
search, `?ids=` lookup) through `lib/school-api.ts`.

Performance: sorted value arrays are cached per metric, so `rankOf` is a binary search; similar-school vectors are
cached per loaded dataset (`WeakMap` in `lib/insights.ts`).

### Adding newer primary-source figures
The sync covers every school. To layer in newer or verified figures (e.g. a Common Data Set published before IPEDS
catches up), add an entry to `data/overrides.json` (see [data-sync.md](data-sync.md)). Vanderbilt (`221999`) is the
example. Recipe for finding the numbers:
- **Admissions, test scores, enrollment, race/ethnicity**: the school's Common Data Set (sections C1, C9, B1, B2).
  Race shares use the "Total undergraduates" column; `other` = American Indian + Pacific Islander + unknown.
- **Pell and first-gen shares**: College Scorecard API (already synced; only override if needed) (`latest.aid.pell_grant_rate`,
  `latest.student.share_firstgeneration`); the CDS doesn't report them. `DEMO_KEY` works for one-off lookups.
- Cross-check: the Scorecard `admission_rate.overall` should equal CDS admitted ÷ applied.
- `unit_id` is the IPEDS ID; `region` follows the existing mapping (TN → Southeast).
