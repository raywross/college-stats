# Architecture

## Tech Stack

| Layer | Technology | Purpose |
|---|---|---|
| Framework | Next.js 16 (App Router) | SSR, routing, API routes |
| Language | TypeScript (strict) | Type safety |
| Styling | Tailwind CSS v4 + shadcn/ui (base-ui) | Accessible, composable UI |
| Theming | next-themes | System/light/dark mode switching |
| Charts | Custom SVG/CSS components (`components/charts`) | Full design control, theme-token colors |
| Data (source) | `data/schools.json` built from College Scorecard + IPEDS, reviewed in git | ~1,900 4-year colleges |
| Data (serving) | The JSON files, shipped with every deploy and read from disk once per server instance | [serving-architecture.md](serving-architecture.md) |
| Data (people, high schools, change log) | Supabase (PostgreSQL) | [supabase.md](supabase.md) |
| Data sync | `npm run sync-data` (Scorecard API + IPEDS bulk CSV); a merge deploys the result | `npm run publish-changes` records what changed after each deploy; `npm run publish-high-schools` fills the high-school table |

## Key Architectural Decisions

### 1. Data Access Abstraction
All data goes through `const data = await getData()` from `lib/data.ts`, which returns the query functions
(`getSchools(filters)`, `getSchoolById(id)`, `rankOf(school, metric)`, …) bound to one loaded copy of the dataset.
Where that copy comes from (JSON files or Supabase) is decided only in `lib/data.ts`. See
[data-layer.md](data-layer.md) and [supabase.md](supabase.md).

### 2. URL-Driven State
Search filters are stored in URL search params (`?state=CA&minSAT=1200`). This makes:
- Searches shareable/bookmarkable
- Back/forward navigation work naturally
- Server-side rendering possible

### 3. Client vs Server Components
- **Server Components** (default): Pages, data fetching, layout
- **Client Components**: Interactive filters, charts, theme toggle, comparison selection
- Minimize `"use client"` boundaries to keep bundle small

### 4. No Global State Library
React `useState` + URL params + localStorage (for compare list) are sufficient for MVP.

### 5. Dark Mode & Design Tokens
See [design-system.md](design-system.md). All colors are CSS variables with chosen light and dark values.

### 6. Responsive
Mobile-first; see the table in [design-system.md](design-system.md#responsive).

### 7. Server-first charts
Static charts are server components. Interactive charts are client components that receive plain data only;
formatting is passed as a `FormatKind` string, never as a function.

### 8. Drill-down navigation
Home (all schools) → Explore (filtered set; grid/table/chart/map) → Profile (one school: overview cards, then a page per topic) → any dot,
similar school, or compare link leads sideways. Glossary pop-overs are available at every level.
